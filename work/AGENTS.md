# agents.md

このディレクトリは、Expo アプリを開発する devcontainer のルートです。複数の Expo プロジェクト（例: `my-app`, `my-app2` など）をこの直下に並べて配置します。本書は、この環境でのプロジェクト追加・運用ルールを簡潔にまとめたものです。詳細なコマンド例は `readMe.md` も参照してください。

## 目的

- ルート直下に複数の Expo アプリを共存させ、各プロジェクトを独立して開発・起動できるようにする。
- 新規プロジェクト作成手順と、日常の開発フローを統一する。

## ディレクトリ構成

- ルート（本ファイルのある階層）直下に、各アプリごとのディレクトリを作成します。
  - 例: `my-app/`, `my-app2/` など
- 各アプリはそれぞれ独立した Node パッケージ（`package.json`・ロックファイル）として管理します。
- ルートには共通のコードは原則置かず、各アプリ配下に完結させます。

## 新規プロジェクトの作成

`readMe.md` に準拠し、以下の手順で新規作成します（テンプレートは一例）。

```bash
# 1) Expo アプリを作成（例: blank テンプレート）
npx create-expo-app@latest my-app --template blank

# 2) 作成したディレクトリに入る
cd my-app

# 3) 依存をインストール（pnpm を使う場合は pnpm に読み替え）
npm install
```

- ディレクトリ名は一意となるようにし、ハイフン区切り（`new-project-name` など）を推奨します。
- 既存ディレクトリ直下に `create-expo-app` を実行しないでください（予期せぬ上書き・競合を防ぐため）。

### アプリ専用 AGENTS.md の作成（サンプルベース）

- 目的: 各アプリの開発・運用ルールをそのディレクトリ内に明文化し、オンボーディングと統一を促進する。
- サンプル: ルート配下の `my-app/AGENTS.md` をベースに複製・編集します。

例:

```bash
# ルート直下で新規作成したアプリ名を new-app とする
cd new-app
cp ../my-app/AGENTS.md ./AGENTS.md

# 必要に応じて内容を自分のアプリ向けに修正
$EDITOR ./AGENTS.md
```

- 最低限の更新項目:
  - アプリ名/説明、主要コマンド（start/test など）、使用パッケージマネージャの表記
  - リンター/フォーマッタの方針、テスト方針、セキュリティ注意点
- 配置場所: 各アプリ直下に `AGENTS.md` を必ず置くこと。
- 運用: 仕様やフローが変わったら各アプリの `AGENTS.md` を更新してください。

## 開発・起動

各プロジェクトディレクトリに移動して起動します。

```bash
cd my-app
npx expo start   # または npm start
```

- Web/Android/iOS の起動は Expo 開発ツールから選択してください。
- Dev Container 内でのポート/トンネリング設定は、環境のガイドラインに従ってください。

## パッケージ管理

- 各プロジェクトは独立して依存を管理します。
  - そのプロジェクト内のロックファイル（`package-lock.json` / `pnpm-lock.yaml`）に合わせて同一のパッケージマネージャを使用してください。
- 依存追加例（npm の場合）:

```bash
cd my-app
npm install <package-name>
```

## コーディング・運用ルール（推奨）

- ESLint/Prettier などの設定は各アプリ配下に配置し、アプリ単位で整合性を保ちます。
- 共通化が必要なユーティリティは、まずは各アプリに複製せず、要件が固まった段階で別パッケージ化を検討してください。

## コミットメッセージ規約

- コミットメッセージは日本語で書き、一般的なプレフィックス（`feat`/`fix`/`docs`/`refactor`/`test`/`chore`/`ci`/`build` など）を先頭に付ける。
- プレフィックスは変更の種類を示すために付与し、`feat: ログイン画面を追加` のように使う。
- `feat`: 新機能の追加を示す。
- `fix`: 不具合の修正を示す。
- `docs`: ドキュメントのみの変更を示す。
- `refactor`: 挙動を変えない内部改善を示す。
- `test`: テスト追加や修正を示す。
- `chore`: ビルドや補助的作業など、運用上の雑多な変更を示す。
- `ci`: CI 設定やワークフロー変更を示す。
- `build`: ビルド設定や依存関係の変更を示す。

## よくある作業フロー

- 新しいアプリを追加する: 上記「新規プロジェクトの作成」を実施（`my-app3` など、重複しない名称で）。
- 既存アプリを起動する: 対象ディレクトリへ移動して `npx expo start`。
- 依存を更新する: 各アプリ配下で `npm update` などを実行。

## コミュニケーションルール

- 日本語でのやり取りが必須
- セッション開始時に `codex/todo.md`（無ければ `TODO.codex.md`）を確認
- 重要な意思決定は `codex/chat-YYYY-MM-DD.md` に簡潔に記録（機密は記載しない）
- コマンド実行や依存追加など影響の大きい操作は意図 → 承認 → 実行 → 差分要約の順で進める
